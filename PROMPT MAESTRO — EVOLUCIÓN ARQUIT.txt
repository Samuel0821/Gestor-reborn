# 11. ATRIBUTOS DINÁMICOS

Los atributos específicos de una industria NO deben convertirse indiscriminadamente en columnas permanentes de `products`.

Debes evaluar una estructura como:

```text

```

y una relación como:

```text

```

o una solución equivalente compatible con la arquitectura existente.

Ejemplo:

```text

Herramienta

material = acero

```

Otro producto podría tener:

```text
PRODUCTO:
Camisa

ATRIBUTOS:
talla = M
color = azul
material = algodón
género = masculino
```

Otro:

```text
PRODUCTO:
Aire acondicionado

marca = LG
modelo = XYZ
BTU = 12000
voltaje = 220V
refrigerante = R32
```

La misma tabla `products` debe soportar los tres casos.

```text
resetDatabase()
```

como parte de una actualización.

Las migraciones deben:

* tener versión.
* ejecutarse una sola vez.
* ser idempotentes cuando sea posible.
* conservar información.
* verificar columnas existentes.
* verificar tablas existentes.
* utilizar transacciones cuando sea posible.
* registrar errores.
* registrar versión aplicada.

Antes de modificar una base existente:

```text
BACKUP
↓
MIGRATION
↓
VALIDATION
```
